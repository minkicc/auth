# Security Policy

## Reporting A Vulnerability

Do not open a public issue for a suspected vulnerability. Before the first public release, enable private vulnerability reporting for the `example/auth` repository or replace this notice with a monitored security address.

Include the affected version or commit, impact, affected component, reproduction steps, and any proof of concept. Do not include live credentials or personal data.

## Supported Versions

The supported release channel and response targets must be documented when the public mirror is announced. Until then, treat the repository as unreleased development software.
